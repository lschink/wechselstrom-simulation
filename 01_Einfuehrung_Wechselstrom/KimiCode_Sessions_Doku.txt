================================================================================
KIMI CODE CLI - SESSIONS SPEICHERN, EXPORTIEREN UND WIEDER AUFNEHMEN
================================================================================
Erstellt: 2026-10-11
Quelle:   https://www.kimi.com/help/kimi-code/cli-sessions
--------------------------------------------------------------------------------

1. GRUNDPRINZIP
--------------------------------------------------------------------------------
Kimi Code CLI speichert jede Konversation automatisch als "Session" inklusive
Nachrichtenverlauf und Metadaten. Das Terminal kann jederzeit geschlossen
und die Arbeit spaeter exakt an derselben Stelle fortgesetzt werden.
Ein Export ist zum Weitermachen NICHT noetig - Sessions liegen lokal vor.

2. SPEICHERORT DER SESSIONS
--------------------------------------------------------------------------------
Alle Sessions liegen unter:

    $KIMI_CODE_HOME/sessions/        (Standard: ~/.kimi-code/sessions/)

Sie werden nach Arbeitsverzeichnis gruppiert abgelegt. Wichtige Dateien:

    state.json              Session-Metadaten (Titel, Erstellungszeit)
    agents/*/wire.jsonl     Agent-Ereignisstrom fuer Wiederherstellung
                            und Replay; enthaelt auch Request-Trace
                            (Tool-Schemas, Request-Parameter, MCP-Tools)

ACHTUNG: Dateien im sessions/-Verzeichnis NICHT von Hand bearbeiten -
das kann die Wiederherstellung der Session zerstoeren.

3. SESSION FORTSETZEN (WIEDER AUFNEHMEN)
--------------------------------------------------------------------------------
Jeder direkte Aufruf von `kimi` startet eine NEUE Session.

Letzte Session im aktuellen Verzeichnis fortsetzen:

    kimi --continue

Bestimmte Session anhand der ID fortsetzen:

    kimi --resume <session-id>

Hinweis: `--continue` und `--session` schliessen sich gegenseitig aus.

4. SESSION-VERWALTUNG IM TUI (Slash-Kommandos)
--------------------------------------------------------------------------------
Nur verfuegbar, solange der Agent im Leerlauf (idle) ist:

    /new  (Alias /clear)     Neue Session, aktueller Kontext wird verworfen
    /sessions (Alias /resume) Verlauf durchsuchen und Session wiederherstellen
    /fork                    Aktuelle Session abzweigen (siehe Kapitel 6)
    /title <text> (Alias /rename)  Session-Titel setzen (ohne Arg.: anzeigen)

5. EXPORT
--------------------------------------------------------------------------------
Session als ZIP packen (fuer Sharing, Archivierung, Bug-Reports):

    kimi export                 # letzte Session im Verzeichnis (fragt nach,
                                # mit -y Bestaetigung ueberspringen)
    kimi export <session-id>    # bestimmte Session
    kimi export -o pfad/ziel.zip  # Ausgabepfad angeben

Der Export enthaelt alle Dateien des Session-Verzeichnisses inkl.
Diagnose-Logs. Das globale Log (~/.kimi-code/logs/kimi-code.log) wird
standardmaessig mitgepackt; ausschliessen mit:

    kimi export --no-include-global-log

Export direkt im TUI (ohne interaktive Sitzung zu verlassen):

    /export-debug-zip          # dasselbe Debug-ZIP wie `kimi export`
    /export-md  (Alias /export)  # lesbares Markdown-Protokoll; optional mit
                               # Pfad-Argument, sonst:
                               # kimi-export-<short-id>-<timestamp>.md

Web-UI: Dort laedt /export die aktuelle Session als Diagnose-ZIP herunter
(inkl. persistierter Session-Daten, Logs, metadatenbasierter Browser-Events;
Prompt-Texte und WebSocket-Inhalte sind NICHT enthalten). Das Web-Kommando
verhaelt sich anders als der TUI-Alias /export.

SICHERHEITSHINWEIS: Export-Dateien koennen Code, Befehlsausgaben und
Dateipfade enthalten. Inhalt vor dem Teilen pruefen!

6. SESSION FORKEN (ABZWEIGEN)
--------------------------------------------------------------------------------
Mit /fork eine unabhaengige Kopie der aktuellen Session erstellen, um neue
Ideen zu testen, ohne die laufende Konversation zu stoeren:

    /fork

- Man bleibt nach dem Fork in der ORIGINAL-Session; diese bleibt unveraendert.
- Die Kopie ist voellig unabhaengig und kann ueber /sessions erreicht werden.
- Ein gespeichertes /goal wird NICHT mitkopiert (dort neu starten noetig).
- Nach dem Fork gibt die CLI ein fertiges `kimi --resume`-Kommando aus
  (wird automatisch in die Zwischenablage kopiert).

7. KONTEXTKOMPRESSION
--------------------------------------------------------------------------------
Bei langen Gespraechen komprimiert die CLI den Verlauf automatisch, wenn
das Kontextfenster fast voll ist. Manuell ausloesen:

    (Kommando im TUI, siehe Hilfe / Kommando-Referenz)

Beim Komprimieren kann ein Hinweis uebergeben werden, welche Informationen
prioritaet behalten werden sollen.

8. PRAKTISCHE EMPFEHLUNG
--------------------------------------------------------------------------------
- Auf derselben Maschine weiterarbeiten: einfach `kimi --continue` bzw.
  `kimi --resume <id>` - kein Export noetig.
- Kein offizieller "Import" einer Export-ZIP vorgesehen; die ZIP dient dem
  Teilen/Archivieren.
- Uebertragung auf anderen Rechner: Verzeichnis unter
  ~/.kimi-code/sessions/ kopieren (inoffiziell, auf eigene Gefahr).
